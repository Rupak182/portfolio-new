Caching is one of the most effective ways to scale an application by storing copies of frequently accessed data in a fast-access storage layer (typically RAM).

## Cache Placement Strategy

Caching can be applied at multiple layers of a system architecture:

1.  **Client-Side Caching**: Storing resources locally in the browser or mobile app.
2.  **CDN (Content Delivery Network)**: Serving static assets and media from edge servers closest to the user.
3.  **API Gateway / Reverse Proxy**: Caching HTTP responses directly at the server entrance.
4.  **Application Caching**: Storing computing results, user sessions, or shared configuration inside the application memory.
5.  **Database Caching**: Storing database query results in a cache layer like Redis or Memcached.

## Common Caching Patterns

*   **Cache-Aside (Lazy Loading)**: The application checks the cache. If not found (cache miss), it reads from the database, stores it in the cache, and returns it.
*   **Write-Through**: The application writes data to the cache, which synchronously updates the database.
*   **Write-Behind (Write-Back)**: The application writes data to the cache, and a separate process updates the database asynchronously.

## Cache Eviction Policies

When the cache reaches its memory limit, it must discard older entries. Common algorithms include:
*   **Least Recently Used (LRU)**: Discards the least recently accessed items first.
*   **Least Frequently Used (LFU)**: Discards items that are accessed the least number of times.
*   **First In, First Out (FIFO)**: Discards items in the order they were added.
